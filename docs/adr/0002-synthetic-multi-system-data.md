# ADR 0002 — Use synthetic multi-system data

## Status

Accepted

## Context

The agent needs more than one system, and the systems need to disagree. A home project does not have production CRM, ERP, or warehouse access. Borrowing a real extract would also put customer data on a laptop and make the answer key unknowable.

The gaps have to be realistic enough to discuss in an interview and stable enough to score.

## Decision

Ship three SQLite databases, generated by `gap_agent.synthetic.generate`:

- `crm.sqlite` — customers and contacts, worded status values, current timestamps
- `erp.sqlite` — customers, products, orders, one undocumented table, letter status codes, some null emails
- `warehouse.sqlite` — a stale dimensional extract, numeric status codes, one customer with no source key, two CRM customers omitted

Gaps are constants in the generator, not random draws. `data/ground_truth/metrics.json` is recomputed from the files on each run. `known_gaps.md` explains them in words. The official catalog deliberately omits `legacy_cust_dump`.

About twenty customers and fourteen orders is enough. Volume is not the point.

## Consequences

- Anyone can regenerate the lab with one command and get the same gaps.
- Evaluation can use precision against the known list. A finding that is not in that list is either a bug in the agent or a bug in the generator, and both are useful.
- The demo must not be described as a scan of a real enterprise. It is a controlled stand-in for that problem.

## Alternatives considered

One database with a few nulls would not show cross-system identity or freshness. A public Kaggle dataset would be larger and would not contain a designed answer key. PostgreSQL schemas would look more like a company standard and add a server the first weekend does not need. SQLite files can move to schemas later without changing the agent tools.
